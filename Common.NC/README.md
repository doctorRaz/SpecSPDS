# Common.NC

**Common.NC** — библиотека общих команд и вспомогательных CAD-сервисов для приложений, работающих в nanoCAD. Она предназначена для повторного использования общей функциональности аддона, а не для реализации продуктовой бизнес-логики.

## Состав

### Общие команды

Команды регистрируются через атрибуты Teigha.Runtime.CommandMethod. К фактическому имени команды добавляется CommandPrefix.Value; значение префикса определяется настройками сборки.

| Суффикс команды | Назначение |
| --- | --- |
| _CommandInfo | Вывод списка объявлений команд и диагностика дублирующихся имён |
| _DiagnosticLevel | Просмотр, установка или сброс уровня Internal Logger |
| _LogLevel | Просмотр, установка или сброс уровня основного логирования |
| _Settings | Настройка вывода сведений о командах при запуске |
| _UpdateCheck | Ручной запуск проверки обновлений |
| _UpdateMode | Настройка режима и интервала автоматической проверки обновлений |

Фактическое имя команды — значение CommandPrefix.Value плюс указанный суффикс. Префикс может различаться в зависимости от конфигурации сборки.

### CAD-сервисы

- **KeywordOption** — описание варианта выбора: глобальное и локальное имя, отображаемое имя, возвращаемое значение, признак варианта по умолчанию, видимости и доступности.
- **KeywordPrompt** — показывает варианты через PromptKeywordOptions и возвращает связанное значение Enum. При отмене или нераспознанном результате возвращает null; при разрешённом пустом вводе возвращает значение варианта по умолчанию, если он задан.
- **EnumExtensions.DisplayName()** — возвращает описание перечисления из DescriptionAttribute, а при его отсутствии — имя значения.
- **CmdInfo** — собирает объявления CommandMethodAttribute из заданных сборок, предоставляет списки уникальных и дублирующихся имён команд. Ошибки рефлексии отдельных типов или методов журналируются, если передан логгер, и не должны прерывать весь сбор.

### AddOnContext

AddOnContext предоставляет общим командам доступ к сервисам аддона через статические свойства. Сервисы поступают через IAddOnServices; контекст должен быть инициализирован точкой входа аддона до вызова команд.

Инициализация:

~~~csharp
AddOnContext.Initialize(addOnServices);
~~~

Повторная инициализация тем же экземпляром сервисов допустима. Передача другого экземпляра после инициализации приводит к InvalidOperationException. До инициализации обращение к AddOnContext.Services также приводит к InvalidOperationException.

Через контекст доступны, в частности, сведения об аддоне и CAD-хосте, сервисы документов и сообщений, фабрика логгеров и настройки аддона. Реализации сервисов регистрируются вне Common.NC.

## Настройки

Команда _Settings управляет General.ShowCommandInfoOnStartup. Команда сохраняет изменения через IAddonSettings.Save(). Если сохранение завершается ошибкой, значение в памяти возвращается к прежнему.

Команда _UpdateMode изменяет IUpdateSettings.Mode и UpdateCheckIntervalDays. Допустимый ввод периода в команде — от 1 до 30 дней. Режим и период сохраняются через IAddonSettings.Save(); при ошибке сохранения оба значения восстанавливаются.

Поддерживаемые режимы обновления:
- **Disabled** — обычные обновления отключены; обязательные обновления обрабатываются согласно политике Updater;
- **CheckAndNotify** — проверка с подтверждением установки;
- **CheckAndInstall** — автоматическая установка необязательных обновлений.

Команда _UpdateCheck запускает проверку с режимом UpdateLaunchMode.Manual, используя зарегистрированные сервисы, настройки и сведения об аддоне.

## Управление уровнями логирования

Команды _LogLevel и _DiagnosticLevel управляют файлами настроек рядом со сборкой аддона:

| Файл | Назначение |
| --- | --- |
| logger.level | Уровень основного логирования |
| diagnostic.level | Уровень Internal Logger NLog |

Команды позволяют задать уровень, удалить переопределение или показать текущее значение. Файлы читаются при инициализации логирования, поэтому для применения изменения требуется перезапустить nanoCAD.

## Зависимости и архитектурные границы

Проект нацелен на net6.0-windows и собирается с константой NC. Он ссылается на проекты Abstractions и Updater.

Common.NC использует абстракции для сервисов логирования, сообщений, настроек и инфраструктуры. Конкретные реализации этих сервисов и их регистрация принадлежат приложению и его инфраструктурным проектам; библиотека не должна подменять их собственными реализациями.

Вспомогательные классы используют API CAD-хоста (HostMgd, Teigha.Runtime). Это библиотека для nanoCAD-среды, а не универсальная библиотека .NET.

## Подключение

1. Добавить ссылку на Common.NC.csproj в проект аддона.
2. Зарегистрировать реализации необходимых абстракций в контейнере/сервисах приложения.
3. В точке входа аддона инициализировать AddOnContext вызовом AddOnContext.Initialize(addOnServices).
4. Обеспечить, чтобы инициализация контекста завершилась до вызова общих команд.
5. Настроить CommandPrefix.Value в соответствии с принятой схемой имён команд продукта.

Пример вызова CAD-сервиса:

~~~csharp
Enum? answer = KeywordPrompt.GetAnswer(
    document,
    options,
    "\nВыбери вариант: ",
    allowNone: true);
~~~

Если пользователь отменил ввод или результат не сопоставлен с вариантом, метод возвращает null. При разрешённом пустом вводе возвращается значение варианта, помеченного как IsDefault, либо null, если такой вариант не задан.
