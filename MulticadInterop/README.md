# MulticadInterop

Библиотека-обёртка для доступа к API Multicad без compile-time зависимости от конкретной версии Multicad.

## Назначение

`MulticadInterop` позволяет общим библиотекам и сервисам обращаться к API Multicad через reflection. Это позволяет не добавлять ссылки на Multicad SDK в проекты, которые должны оставаться независимыми от конкретной версии CAD-платформы.

Публичный код работает через обычный API-обёрток `MulticadInterop`; детали reflection скрыты внутри библиотеки.

## Реализованные API

Сейчас реализованы обёртки для:

- `McNotificator` — вывод сообщений и уведомлений.
- `McParamManager` — чтение и установка параметров, вызов диалога настроек.

При необходимости новые API Multicad добавляются по тому же принципу.

## Принцип работы

1. При вызове обёртки библиотека ищет соответствующий тип Multicad среди уже загруженных сборок.
2. Нужный метод находится по имени и сигнатуре.
3. Вызов выполняется через reflection.
4. Наружу возвращается типизированный результат обычного API обёртки.

Поэтому `MulticadInterop` не требует ссылки на Multicad SDK при компиляции.

## Требования

API Multicad, с которым работает конкретная обёртка, должен быть загружен в процесс во время выполнения.

Если соответствующий API не найден, обёртка сообщает об этом через `InvalidOperationException`.

## Добавление новых обёрток

Перед реализацией нового API необходимо определить фактические публичные сигнатуры соответствующей версии Multicad. Для этого используется **Обозреватель объектов Visual Studio**.

После этого:

- создаётся reflection-класс поиска типов и методов;
- создаётся типизированная публичная обёртка;
- reflection-детали не выносятся в код потребителей;
- публичные методы документируются XML-комментариями.

Обёртка должна учитывать возможные различия namespace и сигнатур между поддерживаемыми версиями Multicad.
