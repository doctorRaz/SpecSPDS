# Updater

Библиотека `dRz.Updater` проверяет доступность обновления, загружает опубликованный архив, проверяет его целостность и устанавливает файлы в каталог аддона. Библиотека предназначена для использования основным аддоном; она не определяет внутреннюю структуру продукта, кроме согласованного пути внутри архива.

## Требования и зависимости

- .NET 6, Windows (`net6.0-windows`).
- Ссылка на проект `Abstractions` для логирования и сообщений.
- NuGet-пакет `SharpSevenZip` для распаковки 7z.
- Источник обновлений должен отдавать `update.json` и архив, указанный в его метаданных, по HTTP или HTTPS.

Updater **распаковывает** архивы, но не создаёт их. Для загрузки используются временный каталог и HTTP(S); после завершения операции временный каталог удаляется.

Для распаковки используется `SharpSevenZip` версии `2.0.128`, а не внешний `7z.exe`. Нативная библиотека `7z.dll` должна находиться в каталоге рядом со сборкой Updater в подпапке `x64` или `x86` в соответствии с разрядностью процесса. Путь вычисляется относительно расположения сборки Updater, а не основного аддона. Пароль передаётся библиотеке при открытии архива; поддерживаются 7z-архивы с зашифрованными заголовками.

## Использование

Основной аддон передаёт Updater настройки обновления через `IUpdateSettings`, а в запросе — актуальную версию, базовый URL и каталог установки:

```csharp
using dRz.Updater;
using dRz.Updater.Services;
using dRz.Abstractions.Updater;
using dRz.Abstractions.Settings;

// IMessageService, IMessagePromptService и IDrzLoggerFactory
// предоставляет инфраструктура основного аддона.
IUpdateSettings updateSettings = addonSettings.Updates;
var updateManager = new UpdateManager(messageService, promptService, loggerFactory, updateSettings);

var request = new UpdateRequest
{
    CurrentVersion = currentVersion,
    UpdateUrl = "https://example.org/releases/",
    PackageDirectory = addOnDirectory,
    IsPackage = true
};

UpdateResult result = await updateManager.RunAsync(request, cancellationToken);
```

Это пример контракта: `messageService`, `promptService`, `loggerFactory`, `currentVersion` и `addOnDirectory` должны быть предоставлены вызывающим кодом. URL в примере условный.

### Параметры запроса

- `CurrentVersion` — установленная версия в формате `System.Version` с четырьмя компонентами.
- `UpdateUrl` — **базовый URL каталога**, содержащего `update.json`. Если URL не заканчивается на `/`, Updater добавляет разделитель при разрешении относительных путей.
- `IUpdateSettings.Mode` — режим проверки/установки, хранящийся в настройках аддона; передаётся в `UpdateManager` отдельно от `UpdateRequest`.
- `LaunchMode` — способ запуска из `UpdateLaunchMode`. По умолчанию `Automatic`: используется режим из `IUpdateSettings`. При `Manual` режим принудительно становится `CheckAndNotify` для необязательных обновлений; обязательные обновления устанавливаются без подтверждения.
- `PackageDirectory` — полный путь к каталогу, в который устанавливаются файлы обновления. Должен указывать на каталог установленного аддона/модуля, а не на временный каталог распаковки.
- `IsPackage` — определяет структуру каталога внутри архива. При `true` файлы берутся из `<распаковка>/<product>/`; при `false` — из `<распаковка>/<product>/<имя PackageDirectory>/`. Имя последнего каталога вычисляется из `PackageDirectory`.
- `IsNetworkPath` — признак того, что основная сборка аддона загружена с сетевого расположения. Если `true`, Updater прекращает работу до сетевых запросов и создания временных файлов; обновление должен выполнять администратор.

### Результат RunAsync

Метод `RunAsync` возвращает `Task<UpdateResult>`. Результат размещён в `dRz.Abstractions.Updater`, чтобы основной аддон и другие проекты могли использовать контракт без зависимости от реализации Updater.

| Результат | Значение |
| --- | --- |
| `Installed` | Обновление успешно установлено. |
| `UpToDate` | Обновление не требуется. |
| `Declined` | Пользователь отказался от необязательного обновления. |
| `Disabled` | Установка необязательного обновления отключена настройками. |
| `NetworkPath` | Обновление не выполнялось из-за сетевого расположения аддона. |
| `Failed` | Проверка или установка завершилась ошибкой; подробности записываются в журнал. |
| `Cancelled` | Операция отменена через переданный `CancellationToken`. |

Отмена обрабатывается отдельно от ошибки. Она поддерживается во время отменяемых сетевых операций и до начала изменения установленных файлов. Синхронный этап установки не прерывается посередине: это позволяет завершить установку или выполнить откат в согласованном порядке.

## Режимы обновления

| Режим | Поведение |
| --- | --- |
| `Disabled` | Не устанавливает обычные обновления. Для обнаружения обязательного обновления метаданные всё равно загружаются; `mandatory: true` имеет приоритет и приводит к установке. |
| `CheckAndNotify` | При обнаружении необязательного обновления спрашивает пользователя, устанавливать ли его. |
| `CheckAndInstall` | Устанавливает найденное обновление без дополнительного вопроса. |

Обязательное обновление (`mandatory: true`) устанавливается без подтверждения независимо от режима. Для обычного обновления `Disabled` означает отказ от установки.

### Способ запуска (`UpdateLaunchMode`)

`UpdateLaunchMode` задаёт дополнительную обратную связь и влияет на эффективный режим установки:

- `Automatic` — значение по умолчанию; используется `Mode` из `IUpdateSettings`, переданного в `UpdateManager`. При обычной автоматической проверке отсутствие обновлений не сопровождается сообщением пользователю. Ошибки проверки и установки логируются и сопровождаются предупреждением.
- `Manual` — принудительно использует `CheckAndNotify`, независимо от `Mode`: при обнаружении необязательного обновления спрашивает согласие, а при отсутствии обновлений сообщает, что установлена актуальная версия. При ошибке проверки или операции сообщает о неудаче. Подробности ошибки записываются в журнал.

Обязательное обновление устанавливается без подтверждения и при ручном запуске. Для сетевого расположения основной сборки обновление не выполняется независимо от режима; при ручном запуске пользователь получает предупреждение.

## Как определяется тип обновления

Проверки выполняются в следующем порядке:

1. Если версия релиза меньше или равна установленной, обновление не выполняется.
2. Если `mandatory = true`, требуется полное обновление.
3. Если установленная версия ниже `minimumVersion`, требуется полное обновление. Само по себе это условие не отменяет выбор пользователя: режим определяет, будет ли установка автоматической.
4. Если увеличился компонент `Major`, требуется полное обновление.
5. В остальных случаях применяется обычное обновление.

**Обычное обновление** заменяет файлы, присутствующие в новом архиве, с резервированием заменяемых файлов. Файлы, которых нет в новом архиве, остаются на месте.

**Полное обновление** сначала резервирует все файлы целевого каталога, в том числе отсутствующие в новом релизе, затем устанавливает новые файлы. Поэтому файлы, удалённые из состава релиза, не остаются активными после успешного полного обновления.

## Контракт `update.json`

Manifest генерируется скриптом `.github/scripts/New-UpdateManifest.ps1`. Пример структуры:

```json
{
  "product": "SpecSPDS",
  "version": {
    "major": 0,
    "minor": 1,
    "build": 0,
    "revision": 0
  },
  "tag": "SpecSPDS_0.1-release1",
  "asset": "SpecSPDS.zip",
  "sha256": "<SHA-256 обычного архива>",
  "size": 123456,
  "commit": "<commit SHA>",
  "mandatory": false,
  "minimumVersion": {
    "major": 0,
    "minor": 1,
    "build": 0,
    "revision": 0
  },
  "publishedAt": "2026-10-10T12:00:00Z",
  "protected": {
    "asset": "SpecSPDS.7z",
    "sha256": "<SHA-256 защищённого архива>",
    "size": 123456,
    "format": "7z",
    "encryption": "AES-256",
    "encryptedHeaders": true,
    "password": "SpecSPDS"
  }
}
```

Значения размера и SHA-256 в примере условные; реальные значения должны соответствовать опубликованным файлам.

Основные поля:

- `product` — имя продукта; используется как первый каталог внутри архива.
- `version` — версия релиза с четырьмя числовыми компонентами.
- `tag` — тег GitHub-релиза.
- `asset`, `sha256`, `size` — имя, SHA-256 и размер обычного архива.
- `commit` — коммит, из которого собран релиз.
- `mandatory` — признак обязательного обновления.
- `minimumVersion` — обязательный объект версии из четырёх числовых компонентов. Если установленная версия ниже `minimumVersion`, требуется полное обновление. Не передавай `null`: текущая реализация читателя версии ожидает объект, а `null` может привести к ошибке во время проверки.
- `publishedAt` — время публикации в UTC.
- `protected` — необязательные метаданные защищённого архива. Если объект задан, Updater использует его `asset`, `sha256`, `size` и `password` вместо соответствующих верхнеуровневых полей. Сейчас генератор публикует 7z с AES-256 и зашифрованными заголовками.

Поле `password` в публичном `update.json` не является секретом: любой получатель manifest может его прочитать. Шифрование архива затрудняет просмотр содержимого, но не обеспечивает конфиденциальность пароля при таком контракте.

До распаковки Updater проверяет размер и SHA-256 выбранного архива. Если проверка не проходит, установка не начинается.

## Установка, резервирование и откат

- При замене существующего файла он перемещается в резервную копию с суффиксом `.bak`; если имя занято, подбирается следующее уникальное имя.
- Во время установки отслеживаются изменения. При ошибке Updater пытается отменить их в обратном порядке.
- Если откат успешен, исходная ошибка установки обрабатывается как неудача обновления; пользователю сообщается, что прежнее состояние восстановлено.
- Если откат тоже завершается ошибкой, выбрасывается `UpdateRollbackException`. Каталог аддона может оказаться в неполном состоянии; требуется диагностика и при необходимости ручная установка полного релиза.
- Если каталог исходных файлов не существует, `MoveDirectoryFilesWithBackup` возвращает `false`. Ошибки, возникшие во время перемещения файлов, выбрасываются исключениями; при неудачном откате используется `UpdateRollbackException`.

### Очистка резервных копий

В начале `RunAsync`, после проверки входного запроса и до проверки сетевого расположения, выполняется `Cleanup(PackageDirectory)`. Поэтому очистка резервных копий запускается и тогда, когда обновление отключено или аддон загружен с сетевого расположения. Публичный метод `UpdateManager.Cleanup(string addOnDirectory)` также позволяет вызывающему аддону выполнить очистку отдельно.

Очистка удаляет рекурсивно:
- файлы с расширением `.bak`;
- файлы с числовым суффиксом перед расширением, например `Plugin(1).dll` или `Settings(2).json`;
- пустые вложенные каталоги.

Это удаление необратимо. Не вызывайте `Cleanup`, пока резервные копии ещё нужны для восстановления. Шаблон `Имя(число).Расширение` может совпасть и с обычным файлом, созданным не Updater.

## Результат и диагностика

`RunAsync` возвращает `Task<UpdateResult>`. Возможные значения перечислены в разделе «Результат RunAsync» выше; вызывающий код может различить успешную установку, отсутствие обновления, отказ пользователя, отключённый режим, сетевой путь, ошибку и отмену.

Ошибки проверки и установки записываются через соответствующий `IDrzLogger`; ошибки сопровождаются предупреждением пользователю. Если установка завершилась ошибкой после успешного отката, пользователю сообщается, что прежнее состояние восстановлено. Если не удался и откат, сообщается о возможной некорректности установленного каталога и предлагается открыть страницу релиза для ручного восстановления.

Отмена через `CancellationToken` возвращает `UpdateResult.Cancelled`, если токен отменён во время отменяемой операции или до начала изменения установленных файлов. Сама распаковка выполняется синхронным вызовом SharpSevenZip внутри фоновой задачи, запущенной через `Task.Run`; вызывающий код ожидает её завершения. Отмена не прерывает уже начавшийся синхронный этап установки, чтобы не оставить файлы в промежуточном состоянии.

Временный каталог обновления удаляется в блоке `finally`. Ошибка его удаления записывается в журнал и не заменяет результат основной операции.

## Тестирование

В репозитории есть консольный проект `Test.Console.Updater` для локальной проверки. Перед запуском проверьте в тестовом коде URL локального HTTP-сервера, порт и путь к сценарию. Проверяйте на тестовом каталоге, не на действующей установке.

Минимальный набор сценариев:

1. Нет более новой версии.
2. Обычное обновление с заменой существующего файла.
3. Полное обновление, при котором старый файл отсутствует в новом архиве.
4. Ошибка перемещения файла с успешным откатом.
5. Ошибка отката и последующее ручное восстановление.
6. Неверный размер или SHA-256 архива.
7. Зашифрованный 7z с заголовками `-mhe=on`.
8. Каждый режим `UpdateMode`, включая обязательное обновление в режиме `Disabled`.

## Замечание по контракту `minimumVersion`

Генератор manifest допускает отсутствие значения `MINIMUM_VERSION_JSON` и в таком случае записывает `minimumVersion: null`. Это не согласуется с текущей реализацией `UpdateVersionChecker`, которая вызывает `ToVersion()` без проверки на `null`. До отдельного исправления генератора или обработчика manifest публикация должна задавать `minimumVersion` объектом с четырьмя компонентами.
