# LogBootstrap

**LogBootstrap** — библиотека для инициализации системы логирования на базе **NLog**.

## Возможности

- программное создание и настройка `LogFactory` без внешнего `nlog.config`;
- одна кэшируемая фабрика логирования на значение `IAddOnInfo.Product`;
- асинхронная запись основного лога;
- настройка уровней основного логирования и Internal Logger через текстовые файлы;
- вывод Internal Logger в Debug Output, Console и отдельный файл;
- работа прикладного кода через `IDrzLogger` и `IDrzLoggerFactory` без прямой зависимости от NLog.

## Быстрый старт

```csharp
IDrzLoggerFactory loggerFactory =
    NLogBootstrap.GetLoggerFactory(addOnInfo);

IDrzLogger logger =
    loggerFactory.GetLogger<MyClass>();

logger.Info("Started");
```

## Получение фабрики

Главная точка входа:

```csharp
NLogBootstrap.GetLoggerFactory(IAddOnInfo addOnInfo)
```

Фабрика кэшируется по `IAddOnInfo.Product`. Повторные вызовы для одного продукта возвращают ту же фабрику.

При построении конфигурации используются:

- `AssemblyDirectory` — каталог сборки; в нём ищутся файлы `logger.level` и `diagnostic.level`;
- `Product` — идентификатор продукта и ключ кэша фабрики;
- `ProductFamily` — семейство продукта, используемое в именах файлов логов;
- `ProductDataDirectory\logs` — каталог основного и внутреннего логов.

## Уровень основного логирования

Уровень задаётся первой строкой файла `logger.level`, расположенного в `AssemblyDirectory`.

Поддерживаются уровни NLog: `Trace`, `Debug`, `Info`, `Warn`, `Error`, `Fatal`, `Off`.

Если файл отсутствует, первая строка пуста, значение некорректно или файл не удаётся прочитать, используется уровень по умолчанию:

- **Debug-сборка:** `Trace`;
- **Release-сборка:** `Info`.

Уровень считывается при создании фабрики. Поскольку фабрика кэшируется по `Product`, изменение файла само по себе не перенастраивает уже созданную фабрику.

## Уровень Internal Logger

Уровень внутреннего логгера NLog задаётся первой строкой файла `diagnostic.level`, расположенного в `AssemblyDirectory`.

Если файл отсутствует, первая строка пуста, значение некорректно или файл не удаётся прочитать, используется `Off`. Например, значение `Trace` включает наиболее подробное внутреннее логирование NLog.

Internal Logger инициализируется один раз за процесс. При последующих вызовах настройки уровень можно сделать более подробным; запрос `Off` и переход к менее подробному уровню после инициализации не применяются. Поэтому изменение `diagnostic.level` не гарантирует переключение уровня уже работающего Internal Logger.

## Internal Logger: вывод и ротация

Internal Logger выводит сообщения:

- в Debug Output;
- в Console;
- в файл вида `YYYY-MM-DD_<ProductFamily>_internal.log`.

Каталог логов передаётся при настройке; обычно это `ProductDataDirectory\logs`. Если каталог не задан, используется `%TEMP%\dRzTools\logs`.

При инициализации удаляются более старые файлы, подходящие под маску `*_<ProductFamily>_internal.log`, если после сортировки по времени последнего изменения остаётся более пяти файлов. Проверяется также размер текущего файла: если он больше **10 MiB** (10 × 1024 × 1024 байт), файл переименовывается с суффиксом времени `_HHmmss`. Очистка выполняется при инициализации, а не постоянно во время работы.

## Основной лог

Основной лог записывается асинхронно в XML-формате. Имя файла формируется по шаблону:

```text
YYYY-MM-DD_<ProductFamily>.log
```

Основные параметры:

- ротация по дням;
- не более 10 архивных файлов;
- асинхронная очередь на 10 000 событий; при переполнении запись блокируется до освобождения места.

## Файлы настройки

| Файл               | Назначение                    | Расположение        |
| ------------------ | ----------------------------- | ------------------- |
| `logger.level`     | Уровень основного логирования | `AssemblyDirectory` |
| `diagnostic.level` | Уровень Internal Logger       | `AssemblyDirectory` |

Оба файла читаются по первой строке. Дополнительные строки не используются. Внешний `nlog.config` для создания основной конфигурации не используется.

## Архитектура

```text
Application
      │
      ▼
NLogBootstrap
      │
      ▼
NLogFactoryBuilder
      │
      ▼
LogFactory
      │
      ▼
NLogLoggerFactory
      │
      ▼
IDrzLogger
```

## Рекомендации

- Вызывать `NLogBootstrap.GetLoggerFactory()` при инициализации дополнения.
- Использовать одно значение `Product` для сборок, которым нужна общая кэшируемая фабрика.
- Не обращаться к NLog напрямую из прикладного кода.
- Для временной диагностики создать файл `diagnostic.level` с нужным уровнем в `AssemblyDirectory`; учитывать, что Internal Logger инициализируется один раз за процесс.
- Управлять уровнем основного логирования через `logger.level`; изменения применяются при создании фабрики.
