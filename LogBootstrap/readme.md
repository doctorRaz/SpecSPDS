# LogBootstrap

**LogBootstrap** — библиотека для инициализации системы логирования на базе **NLog**.

## Возможности

- автоматическое создание `LogFactory`;
- одна фабрика логирования на продукт (`Product`);
- потокобезопасное кэширование фабрик;
- программная конфигурация NLog без внешнего `nlog.config`;
- асинхронная запись логов;
- чтение уровней основного и внутреннего логирования из файлов;
- вывод Internal Logger в Debug Output, Console и отдельный файл;
- работа прикладного кода через `IDrzLogger` и `IDrzLoggerFactory` без прямой зависимости от NLog.

## Быстрый старт

```csharp
IDrzLoggerFactory loggerFactory =
    NLogBootstrap.GetLoggerFactory(addOnInfo);

IDrzLogger logger =
    loggerFactory.GetLogger<MyClass>();

logger.Info("Started");
```

## Получение фабрики

Главная точка входа:

```csharp
NLogBootstrap.GetLoggerFactory(IAddOnInfo addOnInfo)
```

Фабрика кэшируется по `IAddOnInfo.Product`. Повторные вызовы для одного продукта возвращают ту же фабрику.

Для построения конфигурации используются:

- `AssemblyDirectory` — каталог сборки, где ищутся `log.level` и `diagnostic.mode`;
- `Product` — идентификатор продукта и ключ кэша;
- `ProductFamily` — семейство продукта, используемое в имени основного лог-файла;
- `ProductDataDirectory\logs` — каталог основных логов.

## Настройка уровня логирования

Уровень основного логирования задается первой строкой файла `log.level` в каталоге сборки.

Поддерживаются уровни NLog: `Trace`, `Debug`, `Info`, `Warn`, `Error`, `Fatal`, `Off`.

Если файл отсутствует, пуст или содержит некорректное значение, используется уровень **Info**.

## Diagnostic Mode

Внутренний логгер NLog управляется первой строкой файла `diagnostic.mode` в каталоге сборки.

Если файл отсутствует, используется `Off`. Например, значение `Trace` включает подробное внутреннее логирование NLog.

## Internal Logger

При включенном Diagnostic Mode Internal Logger выводит сообщения:

- в Debug Output;
- в Console;
- в отдельный файл в каталоге логов.

Внутренние логи ротируются и ограничиваются по количеству файлов и размеру текущего файла.

## Основной лог

Основной лог записывается асинхронно. Формат записи — XML. Имя файла формируется по шаблону:

```text
YYYY-MM-DD_<ProductFamily>.log
```

Основные параметры:

- ротация по дню;
- не более 10 архивных файлов;
- асинхронная очередь — 10000 событий.

## Конфигурационные файлы

| Файл | Назначение | Расположение |
|---|---|---|
| `log.level` | уровень основного логирования | рядом со сборкой |
| `diagnostic.mode` | уровень Internal Logger | рядом со сборкой |

Внешний `nlog.config` для построения основной конфигурации не используется.

## Архитектура

```text
Application
      │
      ▼
NLogBootstrap
      │
      ▼
NLogFactoryBuilder
      │
      ▼
LogFactory
      │
      ▼
NLogLoggerFactory
      │
      ▼
IDrzLogger
```

## Рекомендации

- Вызывать `NLogBootstrap.GetLoggerFactory()` при инициализации дополнения.
- Использовать один `Product` для всех сборок одного продукта.
- Не обращаться к NLog напрямую из прикладного кода.
- Для диагностики временно создавать `diagnostic.mode`, а после диагностики удалять его.
- Управлять уровнем основного логирования через `log.level`.
