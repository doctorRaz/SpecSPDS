# LogBootstrap

**LogBootstrap** — библиотека настройки логирования на базе NLog. Она программно создаёт LogFactory и предоставляет прикладному коду абстракции IDrzLoggerFactory и IDrzLogger.

## Возможности

- создание конфигурации NLog без внешнего nlog.config;
- кэширование фабрики по идентификатору продукта IAddOnInfo.Product;
- асинхронная запись основного лога в XML-формате;
- настройка уровня основного лога и Internal Logger через файлы;
- вывод Internal Logger в Debug Output, Console и отдельный файл;
- дневная ротация основного лога и ограничение количества архивов.

## Быстрый старт

~~~csharp
IDrzLoggerFactory loggerFactory =
    NLogBootstrap.GetLoggerFactory(addOnInfo);

IDrzLogger logger = loggerFactory.GetLogger<MyClass>();
logger.Info("Started");
~~~

Вызывать NLogBootstrap.GetLoggerFactory(IAddOnInfo) следует при инициализации аддона. Фабрика кэшируется по Product; повторный вызов для того же значения возвращает ту же фабрику.

## Каталоги и файлы

При создании фабрики используются следующие пути:

| Назначение | Путь |
| --- | --- |
| Файлы настроек уровней | IAddOnInfo.AssemblyDirectory |
| Основной лог | IAddOnInfo.ProductDataDirectory\logs |
| Internal Logger | IAddOnInfo.CompanyDataDirectory\internallogs |

Файлы уровней читаются из каталога сборки:

- **logger.level** — уровень основного логирования;
- **diagnostic.level** — уровень Internal Logger.

Для обоих файлов учитывается только первая строка. Допустимые значения NLog: Trace, Debug, Info, Warn, Error, Fatal, Off. Значение обрезается по краям. При отсутствии файла, пустом или неизвестном значении, а также при ошибке чтения используется уровень по умолчанию.

## Уровень основного лога

Файл logger.level считывается при создании фабрики:

- **Debug:** по умолчанию Trace;
- **Release:** по умолчанию Info.

Изменение файла не перенастраивает уже созданную фабрику. Для применения нового значения требуется перезапуск приложения, чтобы фабрика была создана заново.

## Internal Logger

Уровень Internal Logger задаётся файлом diagnostic.level; значение по умолчанию — Off.

Internal Logger настраивается однократно на процесс. Запрос с уровнем Off не инициализирует его и не блокирует инициализацию другим компонентом. Первый запрос с уровнем, отличным от Off, задаёт конфигурацию. После инициализации повторная настройка не применяется: попытка фиксируется в текущем Internal Logger, если он способен записать сообщение.

Internal Logger выводит сообщения:
- в Debug Output;
- в Console;
- в файл в каталоге CompanyDataDirectory\internallogs (при штатном вызове через NLogBootstrap).

Имя файла имеет формат:

~~~text
YYYY-MM-DD_<GUID>_internal.log
~~~

GUID генерируется при инициализации. Общий каталог может использоваться несколькими аддонами; поэтому очистка не фильтруется по семейству продукта.

При инициализации выполняется обслуживание файлов:
- существующие файлы сортируются по времени последнего изменения от новых к старым;
- из существующих файлов, соответствующих маске *_internal.log, удаляются все после первых **10**;
- затем для текущего лога формируется новый путь с GUID. Поэтому после создания нового файла в каталоге может оказаться **11** файлов с этой маской;
- проверяется размер файла по новому пути. Поскольку имя содержит новый GUID, такой файл обычно ещё не существует и проверка не ограничивает размер ранее созданных файлов.

Очистка и проверка размера выполняются только при инициализации. Исключения в этих обслуживающих операциях подавляются.

Если вызвать InternalLoggerHelpers.ConfigureInternalLogger напрямую без каталога, используется %TEMP%\dRzTools\logs. При штатном вызове через NLogBootstrap каталог передаётся явно.

## Основной лог

Основной лог записывается в XML-формате с атрибутами времени, уровня, имени логгера, PID и имени процесса; сообщение и исключение представлены отдельными элементами.

Имя файла:

~~~text
YYYY-MM-DD_<ProductFamily>.log
~~~

Параметры записи:
- ротация по дням;
- не более **10** архивных файлов;
- асинхронная очередь на **10 000** событий;
- при переполнении очереди запись блокируется до появления свободного места;
- размер пакета асинхронной записи — 500 событий, пауза между пакетами — 50 мс.

## Архитектура

~~~text
Application
    |
    v
NLogBootstrap
    |
    v
NLogFactoryBuilder
    |
    v
LogFactory / NLog
    |
    v
NLogLoggerFactory
    |
    v
IDrzLoggerFactory / IDrzLogger
~~~

## Рекомендации

- Получать фабрику через NLogBootstrap.GetLoggerFactory(IAddOnInfo) при инициализации аддона.
- Использовать IDrzLogger и IDrzLoggerFactory в прикладном коде, не связывая его напрямую с NLog.
- Для временной диагностики создать diagnostic.level в AssemblyDirectory и перезапустить процесс, учитывая однократную инициализацию Internal Logger.
- Для изменения основного уровня создать или изменить logger.level и перезапустить процесс, чтобы фабрика была создана с новым уровнем.
